# Проверка несрабатывающего сброса

## Найдено при чтении кода
- InCallService показывал экран входящего звонка, но не вызывал движок правил.
  Роль основной звонилки не означает наличие отдельной роли CALL_SCREENING.
- Для собственного экрана звонков отсутствовала декларация IN_CALL_SERVICE_UI.
- Исключение при отправке screening-ответа подавлялось, после чего код мог
  записать успешный сброс и отправить SMS.

## Изменения
- При отсутствии отдельной роли screening входящие в состоянии RINGING
  проверяются движком в InCallService; сброс — через Call.reject.
- Повторные события одного вызова не запускают повторную проверку.
- После асинхронной проверки состояние проверяется повторно: уже отвеченный
  или удалённый звонок не отклоняется.
- SMS и переадресация запускаются после события отключения/удаления вызова.
- Контекст номера, SIM, экстренного вызова и сигналов общий для обоих путей.
- При активной роли screening запасной путь не запускается, чтобы не выполнять
  действия дважды. Случаи, когда роль есть, а screening callback не приходит,
  этим исправлением НЕ закрыты и требуют журнала устройства.

## Статус проверки
Сборка и unit-тесты не запущены: в рабочей среде нет Java/JAVA_HOME.
Изменения не включены в готовые APK. Реальные звонки не тестировались.

## Проверки на устройстве после сборки
1. CallShift — основная звонилка, отдельная роль определителя НЕ выдана.
   Главный переключатель включён; правило сброса всех номеров, любая SIM,
   весь день; тестовый номер не в белом списке, исключение повторных отключено.
   Ожидается запрос сброса и запись DIALER_RULES в журнале.
2. Повторить для автоответчика: после отключения — одна SMS, не две.
3. Выдать также роль screening: обработка через SCREENED, без второго действия.
4. Правило PASS, главный переключатель выключен, белый список: вызов проходит.
5. Ответить вручную до завершения проверки: активный вызов не разрывается.
6. Исходящий звонок не отклоняется входящим правилом.
7. Экстренные вызовы проверять только имитацией, не звонить в экстренные службы.
8. Повторить при блокировке экрана и после перезагрузки.

Если вызов проходит: сохранить запись журнала с reason, снимок «Диагностики»
и установленную версию. Отсутствие записи и запись PASS — разные неисправности.

## Исправление выбора конкретной SIM (25.09.2026)
Полевое наблюдение пользователя: правило «Любая SIM» сбрасывает вызов,
а правило конкретной SIM заканчивается PASS/default_policy.

Обнаруженный дефект: список SIM использовал reflection к полю `id` и fallback
через `PhoneAccountHandle.toString()`, хотя публичный `getId()` доступен.
Контекст входящего вызова использовал публичный ID. Теперь список, редактор,
контекст, поиск SIM для действий и автоответчик используют согласованные ID.

Старые значения принимаются только при однозначном сопоставлении с текущими
аккаунтами. Редактор и автоответчик при открытии распознают такие значения;
при сохранении записывается публичный ID. Неоднозначное/неизвестное значение
не заменяется на ANY или первую карту. Если редактор сообщает, что сохранённая
SIM не определена, необходимо заново выбрать нужную карту и сохранить.
Неизвестную SIM входящего звонка нельзя безопасно считать выбранной SIM.

Добавлены PhoneAccountIdsTest (устойчивость к порядку списка, старые значения,
удалённая SIM, неоднозначные значения), регрессия RuleEngine для одной SIM,
другой SIM и неизвестной SIM. Запуск заблокирован отсутствием JDK;
попытка установки JDK также не удалась из-за недоступности apt-репозитория.

После сборки обновления:
1. Выключить отдельный автоответчик для изолированной проверки правила.
2. Открыть правило, выбрать нужную SIM с названием оператора, сохранить.
3. Вызов на выбранную SIM должен отклониться; вызов на другую должен пройти.
4. Повторить после перезапуска приложения.
5. Отдельно проверить автоответчик с той же SIM (и отсутствие SMS для другой).
6. Для неизвестной SIM журнал должен объяснять причину пропуска; ни в коем
   случае не расширять правило на обе SIM автоматически.

## 0.6.4-test: повторные звонки и отправка после отбоя
- Исключение повторных звонков ранее по умолчанию включалось на 3 минуты,
  хотя доменный контракт указывает «выключено». Теперь default — false;
  явный сохранённый выбор пользователя сохраняется.
- Если исключение включено, главный экран явно сообщает, что повторные звонки
  проходят. Выключить: Автоответчик → Настроить → Исключения.
- Постобработка после screening теперь живёт в scope приложения, а не сервиса:
  уничтожение сервиса после respondToCall больше не отменяет отправку.
  Это не гарантия пережить завершение всего процесса ОС.
- Ответ запускается до диспетчера переадресации, чтобы не ждать внешнего канала.
- Настройки автоответчика запрашивают SEND_SMS для SMS / POST_NOTIFICATIONS
  для мессенджера на Android 13+. Отказ отображается пользователю.
- SMS/черновики по-прежнему ограничены одним на номер/канал за 30 минут;
  это не исключение из сброса звонков. Мессенджеры требуют ручной отправки.
