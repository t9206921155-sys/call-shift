# OEM_NOTES.md — особенности оболочек (ТЗ п. 11.2, NFR-5)

CallShift зависит от трёх вещей, которые OEM-оболочки любят ломать:

1. **роль `CALL_SCREENING`** — её могут отозвать или спрятать пункт назначения;
2. **фоновая жизнь процесса** — агрессивная экономия батареи убивает дозвон после отбоя;
3. **собственный системный фильтр вызовов** — он может перехватывать screening раньше нас.

Ниже — проверенные действия по каждой оболочке. Пункты, помеченные ⚠, надо подтвердить
на конкретном устройстве заказчика в M0 (ТЗ п. 17, gate M0).

---

## 1. Google Pixel / AOSP (эталон)

| Шаг | Действие |
|---|---|
| Роль | `Настройки → Приложения → Приложения по умолчанию → Call screening / Определение номера` → CallShift. Либо `adb shell cmd role add-role-holder --user 0 android.app.role.CALL_SCREENING fi.callshift.app` |
| Батарея | `Настройки → Приложения → CallShift → Батарея → Не ограничивать` |
| Системный фильтр | Google Phone («Caller ID & spam») занимает роль screening — при назначении CallShift он её теряет. Вернуть: `adb shell cmd role remove-role-holder --user 0 android.app.role.CALL_SCREENING fi.callshift.app` (ТЗ FR-S1) |
| Замечания | Наиболее предсказуемое поведение; рекомендуется как основное устройство CI-прогона (ТЗ п. 14.2) |

---

## 2. Xiaomi / Redmi / POCO — MIUI и HyperOS

| Шаг | Действие |
|---|---|
| Автозапуск | `Настройки → Приложения → Все приложения → CallShift → Автозапуск (Autostart) = ВКЛ` |
| Батарея | `Настройки → Батарея → (три точки) → App battery saver / Контроль активности → CallShift → Нет ограничений` |
| Фоновые процессы | `Security → Boost speed / Cleaner` — добавьте CallShift в исключения, иначе «очистка» убьёт дозвон |
| Роль screening | Пункт может называться `Caller ID & spam` или отсутствовать в явном виде — используйте adb-команду |
| ⚠ Конфликт | Встроенный «Блокировщик вызовов» (MIUI Phone) сам выполняет screening. Если правила CallShift не срабатывают — отключите системный фильтр или проверьте, кто держит роль: `adb shell cmd role get-role-holders --user 0 android.app.role.CALL_SCREENING` |
| ⚠ Вторая SIM | MIUI любит менять порядок SIM-аккаунтов; селектор правила хранит `HANDLE:<id>`, а не индекс (ТЗ E-15) |

## 3. Samsung — One UI 5/6/7

| Шаг | Действие |
|---|---|
| Сон приложений | `Настройки → Батарея и уход за устройством → Батарея → Ограничения фоновой активности → Never sleeping apps (Не отслеживать)` → добавить CallShift |
| Автозапуск | Отключите `Put unused apps to sleep` для CallShift |
| Роль screening | `Настройки → Приложения → Приложения по умолчанию → Caller ID and spam protection` → CallShift |
| Адаптивная батарея | `Battery protection` / `Adaptive battery` — убедитесь, что CallShift не в категории «ограничено» |
| ⚠ Secure Folder / Dual Messenger | Приложение в Secure Folder получает отдельный профиль; роли туда не наследуются |

---

## 4. Huawei / Honor — EMUI, HarmonyOS

| Шаг | Действие |
|---|---|
| Автозапуск | `Настройки → Батарея → Запуск приложений (App launch) → CallShift → Вручную: включить Автозапуск, Вторичный запуск, Фоновая активность` |
| Оптимизация | `Настройки → Батарея → Оптимизация расхода батареи → Все приложения → CallShift → Не оптимизировать` |
| Роль screening | На устройствах без GMS роль может выдаваться иначе; проверьте через adb и `dumpsys telecom` |
| ⚠ HMS | На устройствах без сервисов Google часть системных диалогов ролей может отсутствовать — обязателен adb-путь |

---

## 5. Oppo / Realme / OnePlus — ColorOS, Realme UI, OxygenOS

| Шаг | Действие |
|---|---|
| Автозапуск | `Phone Manager / Диспетчер телефона → App management → CallShift → Allow autostart` |
| Батарея | `Настройки → Батарея → App battery usage → CallShift → Allow background activity + Allow autostart` |
| Роль screening | `Настройки → Приложения → Управление приложениями по умолчанию` |
| ⚠ App Cloner | Клонированные приложения получают отдельный package id — роли и разрешения надо выдавать заново |

## 6. Общие рекомендации (для всех оболочек)

1. **Не полагайтесь на «зелёную галочку» в настройках.** После каждого обновления прошивки
   проверяйте статус на экране «Диагностика» → «Перепроверить»: оболочка может молча отозвать роль.
   ТЗ п. 11.1 предусматривает watchdog с уведомлением (реализация — M2).
2. **Исключение из оптимизации батареи обязательно**, иначе дозвон на цель (S2) после отбоя
   может не состояться: система успевает заморозить процесс между `respondToCall` и `placeCall`.
3. **Проверяйте роль после установки обновлений приложения** (`MY_PACKAGE_REPLACED`):
   CallShift при старте перепроверяет роли и уведомляет о потере (ТЗ E-01, E-14).
4. **Два screening-приложения одновременно невозможны.** Если вам нужен системный спам-фильтр —
   перенесите его номера в blacklist-правило CallShift (ТЗ FR-S2).
5. **Перед удалением приложения** обязательно выполните `scripts/uninstall_cleanup.sh`:
   сетевая переадресация (MMI) живёт у оператора и не снимается удалением APK (ТЗ E-16).
