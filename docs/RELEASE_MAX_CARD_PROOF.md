## CallShift 0.8.18-max-card-proof

versionCode 50, прежняя подпись, установка поверх текущей версии без удаления данных.

Исправлен конкретный дефект обучения: раньше предварительный номер выбирался среди
ВСЕХ видимых текстов карточки. Посторонний телефон в другом разделе мог остановить
обучение, хотя обычный сценарий проверял только подписанное поле телефона. Обучение
и реальная проверка теперь используют один и тот же метод чтения небольшого раздела
«Номер телефона»/Phone number. Чужой номер вне этого раздела не используется. Два
разных номера внутри раздела, несколько подписей, редактор/пароль, неподходящий или
слишком большой контейнер по-прежнему не разрешают проверку. +7 и 8 нормализуются.

Добавлен отдельный используемый сервисом автомат доказательств обучения:
ручное открытие с подтверждённым телефоном → подтверждённый возврат → одно зарезервированное
автоматическое нажатие → та же карточка с тем же нормализованным телефоном → подтверждённый
финальный возврат → разрешение сохранить действие. Ни одну стадию нельзя пропустить.
Повторная попытка нажатия или неверный переход закрывают текущую цепочку. Номер хранится
только в оперативной памяти на время обучения и удаляется при завершении; в сохраняемом
правиле только интерфейсные признаки, никакой привязки получателя к чату.

Unit-регрессии выполняют всю последовательность, проверяют пропущенные стадии,
повторное нажатие, другой номер, эквивалентность +7/8, сброс сессии, одинаковое чтение
подписанного поля для обучения и обычной проверки. Выпускной workflow также запускает
весь существующий набор тестов и проверяет постоянную подпись APK.

Границы: эти тесты проверяют алгоритм, не реальный Android Accessibility MAX. Исправление
несогласованного чтения поля не доказывает устранение показанного ранее SOURCE_MISSING:
если Android не предоставляет ни источник нажатия, ни поддерживаемый однозначный элемент,
сохраняется остановка. Проверки узлов исходного чата, версии, окна, пустого поля и получателя
не ослаблены. Новых экранов/привязок/координатных нажатий/автоповторов нет.

Сценарий телефона прежний: «Автоответ MAX» → проверка без отправки → явное разрешение →
одна реальная тестовая отправка → получение у адресата. Звонок проверяется отдельно по
правилу нужной SIM с учётом его интервала. Подтверждения полного автоответа на телефоне
пользователя пока нет. При отказе сохраняется обезличенный отчёт из 0.8.17.
