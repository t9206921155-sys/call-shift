# INSTALL.md — установка и настройка CallShift

Документ соответствует ТЗ п. 7.2–7.3 и п. 15.4. Два пути: **ADB** (рекомендуется,
даёт максимум возможностей) и **ручной** (без компьютера, часть функций будет недоступна).

---

## 0. Требования

| Параметр | Значение |
|---|---|
| Android | 9.0 (API 28) и выше. **Роль screening доступна только с Android 10 (API 29)** — на Android 9 нужен профиль B (`ROLE_DIALER`), см. ТЗ D1 и Приложение E (P-8) |
| SIM | Реальная SIM-карта: MMI/USSD и входящие вызовы на эмуляторе не проверяются |
| ПК | `adb` (platform-tools), USB-отладка включена |
| Место | APK ≈ 13 МБ |

---

## 1. Путь A — установка через ADB (рекомендуется)

### 1.1. Собрать или взять готовый APK

Готовый подписанный APK уже находится в репозитории:
`apks/CallShift-v0.2.0-m2-standard-release.apk` (2,9 МБ, подпись v3, minSdk 28).

Для пересборки из исходников:
```bash
cd CallShift
./run_build.sh :app:assembleStandardRelease
```

### 1.2. Один скрипт на всё

```bash
bash scripts/setup_device.sh apks/CallShift-v0.2.0-m2-standard-release.apk
```

Скрипт последовательно:

1. устанавливает APK (`adb install -r -t -g`);
2. выдаёт runtime-разрешения (`pm grant`), включая `ANSWER_PHONE_CALLS`,
   которое **не выдаётся** обычным диалогом;
3. назначает роль `android.app.role.CALL_SCREENING`;
4. (опционально, `SET_DIALER=yes`) назначает роль `android.app.role.DIALER`;
5. добавляет приложение в `deviceidle whitelist`;
6. печатает инструкцию по автозапуску для вашей оболочки;
7. показывает итоговую проверку.

### 1.3. Те же команды вручную

```bash
PKG=fi.callshift.app

adb install -r -t app-standard-release.apk

for p in READ_PHONE_STATE READ_PHONE_NUMBERS CALL_PHONE ANSWER_PHONE_CALLS \
         READ_CALL_LOG WRITE_CALL_LOG READ_CONTACTS POST_NOTIFICATIONS SEND_SMS; do
  adb shell pm grant $PKG android.permission.$p
done

adb shell cmd role add-role-holder --user 0 android.app.role.CALL_SCREENING $PKG
adb shell dumpsys deviceidle whitelist +$PKG

# проверка
adb shell cmd role get-role-holders --user 0 android.app.role.CALL_SCREENING
adb shell dumpsys package $PKG | grep -A 12 "runtime permissions"
```

### 1.4. Контрольный звонок

1. Откройте CallShift → **Диагностика** → убедитесь, что роль `CALL_SCREENING` = ✓,
   а профиль полномочий = `SCREENING` (A) или `DIALER` (B).
2. Создайте правило: маска `+35850*` (или префикс тестового номера),
   вердикт «Отклонить», стратегия «S2 — отклонить и дозвониться», цель — ваш второй номер.
3. Позвоните на устройство с номера, попадающего под маску.
4. Ожидание: вызов сброшен в течение ~1 с, через ~0.8 с пошёл дозвон на цель,
   в **Журнале событий** появилась запись с `reason=rule#…`, `result=OK` и таймингами.
5. Логи в реальном времени: `adb logcat -s CallShift:D`.

## 2. Путь B — установка без компьютера (sideload)

1. Скопируйте APK на устройство (мессенджер, почта, флешка, `adb push` не требуется).
2. Разрешите установку из неизвестных источников для вашего файлового менеджера/браузера.
3. Установите APK.
4. Откройте CallShift → **Мастер настройки**:
   - примите юридическую оговорку (ТЗ, Приложение D);
   - «1. Runtime-разрешения» — выдайте всё, что предлагает система;
   - «2. Роль screening-приложения» — системный диалог назначения роли;
   - «4. Исключение из оптимизации батареи» — подтвердите;
   - «5. Автозапуск в оболочке OEM» — выполните по подсказке (см. `OEM_NOTES.md`).
5. Нажмите **Перепроверить**. Если роль не выдаётся (некоторые оболочки прячут этот пункт),
   придётся вернуться к пути A: `ANSWER_PHONE_CALLS` и роль в ряде случаев выдаются только через adb.

Ручной путь назначения роли (названия пунктов различаются по OEM):

```
Настройки → Приложения → Приложения по умолчанию →
   «Определение номера и спам-фильтр» / «Caller ID & spam» / «Call screening» → CallShift
```

## 3. Что доступно без ADB (профиль A без `ANSWER_PHONE_CALLS`)

| Функция | Работает |
|---|---|
| Отклонение вызова по правилу (`disallow + reject`) | ✅ |
| Отклонение «как пропущенный» | ⚠️ только если метод есть в платформе (reflection, Приложение E P-4) |
| Заглушение звонка (`silence`) | ❌ без `ANSWER_PHONE_CALLS` (ТЗ п. 3.5) |
| Сетевая переадресация MMI (S1) | ✅ (нужен `CALL_PHONE`) |
| Callback-дозвон (S2) | ✅ (нужен `CALL_PHONE`) |
| Уведомления / Telegram / webhook (S4) | ✅ |
| Ответ USSD (`*#21#`) | ⚠️ требует `ANSWER_PHONE_CALLS`, иначе «статус неизвестен» |
| Определение SIM у входящего | ⚠️ best-effort (Приложение E P-2) |

## 4. Обновление версии

```bash
adb install -r app-standard-release.apk
```

Установка поверх возможна **только тем же ключом подписи**. Правила и журнал сохраняются
(хранятся в `filesDir`). При смене keystore сначала выполните раздел 5, затем установите новую сборку
и восстановите правила из экспорта JSON (ТЗ FR-1.7).

## 5. Корректное удаление

```bash
bash scripts/uninstall_cleanup.sh
```

Скрипт **сначала** отправляет `##21#`, `##61#`, `##62#`, `##67#`, `##002#`, `##004#` на каждую SIM
(иначе сетевая переадресация останется у оператора и после удаления приложения — ТЗ E-16),
затем снимает роли, отзывает разрешения и удаляет приложение.

После удаления проверьте состояние вручную: наберите `*#21#` и `*#62#` в штатном телефоне.

## 6. Типовые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| Входящие не перехватываются | роль `CALL_SCREENING` не выдана или отозвана оболочкой | Диагностика → «Перепроверить»; adb-команда из раздела 1.3; watchdog уведомит (ТЗ п. 11.1) |
| «Нет разрешения CALL_PHONE» в журнале | разрешение отозвано/не выдано | `adb shell pm grant $PKG android.permission.CALL_PHONE` |
| MMI возвращает ошибку оператора | оператор/MVNO не поддерживает код, либо SIM в роуминге | проверьте `*#21#` вручную; используйте S2 (ТЗ R-3) |
| Ответ USSD «статус неизвестен» | нет `ANSWER_PHONE_CALLS` | выдайте через adb (ТЗ п. 7.1) |
| Дозвон на цель не идёт | сработал guard (антипетля/антишторм) | смотрите `errorCode` в журнале: `guard_loop_*`, `guard_storm` (ТЗ п. 10.3) |
| После перезагрузки не работает | оболочка убила автозапуск | `OEM_NOTES.md`: автозапуск + «нет ограничений» |
| Приложение не видит, какая SIM | `getPhoneAccountHandle()` скрыт | используйте профиль B (`ROLE_DIALER`) или селектор «Любая SIM» |

Логи: `adb logcat -s CallShift:D Telecom:V`.
