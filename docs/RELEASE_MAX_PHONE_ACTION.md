## CallShift 0.8.11-max-phone-action — «Найти по номеру»

Эксперимент, versionCode 43, прежняя подпись и пакет. Установка поверх текущей версии
без удаления; маршруты SIM → MAX и профиль интерфейса сохраняются.

Скриншот пользователя подтверждает ввод номера и видимое действие «Найти по номеру».
До этого сценарий ожидал результаты списка без нажатия этого действия.

Добавлено:
- Точная подпись «Найти по номеру» (и ограниченные EN эквиваленты), без координат.
  Непустые text/description должны не противоречить друг другу. Звонок и обычная
  кнопка поиска не признаются этим действием.
- Только в уже подтверждённом общем поиске с запросом, который ввёл этот сценарий.
  Запрос обязан точно совпадать с сохранённым, а номер — с получателем с учётом +7/8.
- Действие выполняется один раз за попытку. До нажатия повторно проверяются активное
  окно MAX, разблокировка, отсутствие защищённых полей, единственное поле ввода,
  запрос и однозначная кнопка. Неоднозначность блокирует сценарий.
- Нажатие резервируется до ACTION_CLICK; ошибка или неопределённый результат не
  вызывают повтор. Переходу даётся до 6 секунд в пределах общего лимита 30 секунд.
- Открытый экран — лишь кандидат. Проверки получателя, карточки и пустого черновика
  остаются обязательными. Если вместо чата открывается неподдерживаемый экран,
  отправка запрещена. Отсутствие контакта не обходится.
- В диагностике v7 добавлены FIND_BY_PHONE и отдельные коды ошибки нажатия/неоднозначности.

Проверка без звонка: «Проверить каналы / тестовый ответ» → нужная SIM и номер →
«MAX: тест навигации БЕЗ сообщения». Если после прошлой попытки в MAX остался запрос,
очистите его перед тестом: приложение не затирает оставленные запросы само.
Не нажимайте «Найти по номеру» вручную во время теста. Настройки копий/профиль не
пересоздавайте. При отказе пришлите отчёт v7 из «MAX: эксперимент».

Тесты покрывают точные подписи, конфликт с кнопкой звонка, +7/8, изменённый запрос,
другой номер, имя вместо номера и запрет повторного нажатия. Android-переход и
последующая отправка на устройстве пользователя ещё не проверены. Сначала сухой
тест; разрешение реальной отправки не включается автоматически.
