# Telegram: автоматический ответ от пользовательского аккаунта (экспериментально)

Новый канал `TELEGRAM_ACCOUNT` отделён от прежнего ручного `TELEGRAM`.
Никакая старая настройка не начинает отправлять сообщения автоматически.

## Настройка
1. Правило / Автоответчик → «Подключить Telegram для автоотправки».
2. Получить собственные API ID и API hash на https://my.telegram.org/apps.
   Это реквизиты Telegram API-приложения, не Bot API token. Вводить только в APK.
3. «Подключить», затем ввести номер личного Telegram-аккаунта, код входа
   (может прийти в Telegram, а не SMS), пароль 2FA при необходимости.
   Поддержаны также email и email-код. Регистрация/QR/платный вход не реализованы.
4. Дождаться «Аккаунт подключён», включить разрешение автоматических ответов.
5. В правиле выбрать «Telegram — автоматически (мой аккаунт)», текст и нужную SIM.
   Для изолированной проверки выключить отдельный автоответчик с другими настройками.
6. Сделать тестовый звонок с согласившегося получателя. В журнале должны быть
   отдельные состояния поиска, ожидания Telegram и подтверждения отправки.

## Что происходит
- После решения о сбросе выполняется поиск Telegram `searchUserByPhoneNumber`.
  Адресная книга не импортируется, username не угадывается.
- Отправка разрешается только при совпадении возвращённого номера с номером
  звонящего, обычному пользователю, не себе и не боту.
- Создаётся личный чат и выполняется `sendMessage`. Никакого открытия мессенджера,
  выбора получателя или нажатия «Отправить» во время звонка не требуется.
- Ответ `message` с pending-state НЕ считается отправкой. Подтверждение —
  `updateMessageSendSucceeded` (или финальный Message без sending_state).
- Успех означает подтверждение Telegram, не чтение или получение на конкретном
  устройстве. При таймауте после submit — UNKNOWN, не автоматический повтор.
- Нет оплаты Stars, обхода flood/privacy ограничений, запасной SMS или бота.
- Не чаще одной попытки на номер/канал за 30 минут, включая неудачные попытки.

## Ограничения
Telegram может не раскрыть номер или не найти аккаунт по нему. Тогда отправка
не выполняется — это не гарантированный автоответ любому абоненту.
Нужны интернет и авторизованный аккаунт. При блокировке/отзыве сессии требуется
повторный вход. Фоновый процесс Android может быть завершён; нет гарантии
доставки при force-stop. Пока нет WorkManager-очереди автоматических Telegram
попыток: неизвестные результаты не переотправляются, чтобы не создавать дубли.
Уже принятая Telegram очередь может завершиться после отключения переключателя.
MAX/WhatsApp остаются ручными. Прежний Telegram-канал также ручной.

## Безопасность и зависимости
- Секреты API и ключ шифрования TDLib защищены AES-GCM ключом Android Keystore.
- База TDLib в noBackupFilesDir, зашифрована отдельным случайным ключом.
- Код входа и пароль 2FA не сохраняются приложением, экран защищён FLAG_SECURE.
- Отладочные потоки TDLib отключены, сырые ответы API/номера/секреты не логируются.
- Выход отключает новые автоответы и вызывает TDLib logOut. Если выход не завершён,
  сессию можно отозвать в официальном Telegram → Настройки → Устройства.
- TDLib JNI 1.8.65: сторонняя сборка up9cloud/android-libtdjson, не официальный
  APK Telegram. Артефакт скачивается при сборке и проверяется SHA-256:
  eb777d3e7baedeb02871c691b2090daa1bc51baf9215a81bc55bf54edb76df2b.
  Исходники: https://github.com/up9cloud/android-libtdjson/tree/v1.8.65.
  Лицензии упакованы в assets/TDLIB-NOTICES.txt. Для производственного релиза
  желательно самостоятельно воспроизводимо собирать TDLib и подписывать APK
  постоянным ключом. Хеш гарантирует неизменность, не аудит поставщика.

## Проверки
Unit-тесты проверяют точность адресата, запрет ботов/себя/скрытого номера,
отделение ручного канала, сериализацию настройки, понятную ошибку rate limit.
Реальные вход, 2FA, поиск и отправка требуют разрешённого тестового Telegram
аккаунта. В CI нет пользовательских API credentials или сессии: без живого
теста нельзя объявлять интеграцию проверенной end-to-end.
