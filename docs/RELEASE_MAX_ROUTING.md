## CallShift 0.8.5-max-routing — выбор экземпляра MAX по SIM

Экспериментальная версия, versionCode 37, тот же пакет и постоянная подпись.
Устанавливается поверх 0.8.4 без удаления. Перед обновлением экспортируйте настройки.

### Что сделано
- В MAX передаётся настоящий идентификатор телефонного аккаунта из контекста звонка,
  а не отображаемое имя оператора или предполагаемый порядок SIM.
- «MAX: эксперимент → Аккаунт отправителя по SIM» позволяет один раз указать
  экземпляр MAX для каждой активной SIM. Нет контактов → чатов и привязок получателей.
- Механизм изучает системное окно выбора, без списка производителей и координат.
  Требуются системный пакет, распознаваемый RU/EN заголовок окна открытия приложения,
  две уникальные подписи «MAX» и «MAX (…)» и отдельные доступные кликабельные строки.
  Выбор пользователя сохраняет пакет/версию системного окна, его структурный отпечаток
  и точную подпись. Порядок вариантов не используется для выбора.
- Каждый звонок в режиме клона требует появления изученного окна. Если MAX открылся
  сразу по умолчанию, аккаунт не считается подтверждённым — сценарий останавливается.
  Одно нажатие на изученный вариант, без повторов при неизвестном результате.
- Окно изменилось, SIM неизвестна/удалена, маршрут изменён, вариант неоднозначен,
  окно не доступно Accessibility — остановка. Никаких кликов в обычных чужих приложениях.
- Выбор аккаунта ограничен 8 секундами; общий сценарий по-прежнему 30 секунд.
- Новые маршруты выключают реальную отправку. Для каждой SIM сначала нужен успешный
  проверочный звонок с проверкой получателя. Затем пользователь отдельно разрешает
  отправку. Тест не проверяет доставку и не нажимает кнопку сообщения.
- Диагностика v4: ROUTE_WAIT / ROUTE_PICK / ROUTE_READY, отдельный Stop reason.
  Также различаются причины начального отказа; сохранение профиля больше не
  описывается одной общей ошибкой с выключенным режимом и блокировкой экрана.

Дополнительно: подсказка пустого редактора не считается черновиком только при
явном флаге Android isShowingHintText и точном совпадении text с hintText.
Настоящий текст, даже совпадающий со словом «Сообщение», не стирается.
Это отдельное исправление; причина прошлой остановки пользователя не доказана.

### Настройка двух MAX
1. Подключите службу специальных возможностей, откройте «MAX: эксперимент» →
   «Аккаунт отправителя по SIM» → «Изучить окно выбора двух MAX».
2. Прочитайте и подтвердите разрешение на чтение активного системного окна.
   В появившемся окне не выбирайте MAX. Подождите 2–3 секунды, нажмите «Отмена»
   или «Назад», вернитесь в CallShift. Должно появиться «Окно распознано».
3. Для каждой SIM выберите нужную подпись основного MAX или копии. Android не
   сообщает номер регистрации аккаунта MAX: соответствие аккаунта своей SIM
   подтверждает владелец. Режим «один MAX» нельзя выбирать при наличии клона.
4. Сохранённый ранее профиль чата можно оставить. Если его нет — настройте его
   на экране переписки, затем сохраните. Изучение окна выбора его не заменяет.
5. «Диагностика следующего звонка» → тестовый звонок на настроенную SIM → оставить
   телефон разблокированным. Окно выбора теперь должен пройти сценарий сам.
   Проверьте, какой аккаунт открыт. При отказе скопируйте отчёт v4.
6. До успешной проверки и подтверждения нужного аккаунта реальную отправку не включать.

### Ограничения, которые не сняты
Это общий механизм, а не доказанная поддержка каждого клона на любом Android 9+.
Он не обходит изоляцию профилей, ограничения запуска из фона, Accessibility или
ограничения MAX. Недоступный системе пакет окна, иной заголовок/язык, подписи без
текста, одинаковые подписи или неподдерживаемая структура приводят к отказу.
Данные изученного окна читаются только при явно запущенном обучении (60 сек.)
или при выборе настроенного маршрута в сценарии. В отчёте нет системных подписей,
номеров SIM, имён контактов, resource IDs или содержимого переписки.

Нет автоматической проверки регистрационного номера аккаунта отправителя:
выбирается подтверждённый владельцем экземпляр через доверенное системное окно.
Если аккаунты внутри экземпляров поменялись, владелец должен перенастроить маршруты.
Действия внешнего UI не атомарны — вмешиваться в экран во время сценария нельзя.

Сам поиск получателя, проверка карточки и возврат в чат остаются экспериментальными;
успешный выбор копии не гарантирует их успех. Проверки +7/8 и запреты отправки по
одному имени сохранены. Сборка и тесты не заменяют проверку на реальном устройстве.

### Проверки
Unit-тесты: выбор по точному SIM account ID, отсутствие выбора по имени/номеру слота,
перестановка вариантов, изменённые пакет/версия/структура окна, дубликаты подписей,
неподдерживаемый заголовок, приватность кодов отказа. Android-навигация на устройстве
пользователя пока не проверена.
