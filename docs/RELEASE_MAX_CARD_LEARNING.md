## CallShift 0.8.13-max-card-learning — обучение открытию карточки

Экспериментальная версия, versionCode 45. Постоянная подпись и пакет сохранены.
Установка поверх предыдущей без удаления; маршруты SIM и профиль чата сохраняются.

### Новый режим
MAX: эксперимент → «Обучить открытие карточки — без сообщения».

1. Прочитайте подтверждение: отправка выключается, обучение длится до 60 секунд.
2. Откройте нужную копию MAX вручную и личный чат с пустым полем сообщения.
   Подождите 3 секунды, затем ОДИН раз нажмите имя или аватар, открывающий карточку.
3. Не нажимайте больше ничего. CallShift проверит подписанное поле телефона,
   вернётся в тот же чат, один раз проверит автоматическое нажатие найденного
   элемента и снова вернётся. Сообщения не вводятся и не отправляются.
4. После завершения вернитесь в CallShift. Статус должен сообщить, что действие
   проверено и сохранено. Затем запустите обычный тест MAX без сообщения.

### Что действительно сохраняется
Только версия MAX, IDs заголовка/редактора/цели, класс цели и структурный отпечаток
панели. Это не привязка человека/номера к чату. Имя заголовка и номер карточки нужны
лишь в памяти на время обучения и удаляются при завершении. Отпечаток не содержит
текстов. Хранилище исключено из резервного копирования. Пересохранение профиля чата
удаляет обученное действие, чтобы не применять его к другой конфигурации.

### Проверки
- Свежий снимок шапки (до 1,5 с), источник TYPE_VIEW_CLICKED должен совпасть с узлом
  этого снимка, находящимся в той же панели и вне списков.
- Нужен уникальный resource ID MAX и доступное ACTION_CLICK/кликабельность.
  Никаких координат и угадывания цели по порядку иконок.
- Карточка должна иметь единственный полный телефон возле подписи. После ручного
  и проверочного открытия телефоны совпадают. Номер не сохраняется как получатель.
- Оба возврата должны сохранить идентичность исходных узлов заголовка/редактора,
  окно, подпись заголовка и пустое поле. Это намеренно строгая проверка.
- Сохранение только после автоматического воспроизведения, а не по одному факту
  ручного нажатия. Дополнительные клики останавливают обучение.
- На каждом последующем применении проверяются версия, профиль и структура панели.
  Проверки номера получателя перед вводом/отправкой по-прежнему обязательны.

### Ограничения
Если MAX не выдаёт источник события, стабильный ID или действие ACTION_CLICK,
обучение не сможет создать рабочее правило. Если MAX пересоздаёт узлы при возврате,
оно также остановится. Меню из нескольких переходов не обучается: один тап должен
непосредственно открыть карточку. Не поддерживаем свайпы/координаты и не обещаем
работу любого элемента на всех устройствах.

В диагностике v9 — только код Card learning (WAIT_TAP, SOURCE_MISSING,
SOURCE_REJECTED, CARD_UNVERIFIED, RETURN_UNVERIFIED, REPLAY_FAILED, SAVED и др.).
При отказе нужен этот отчёт, не скриншот переписки.

Unit-тесты проверяют совпадение структурного правила, версию, свежесть снимка,
сериализацию метаданных и сброс кода отчёта. Реальные события Accessibility,
обучение и отправка на телефоне пользователя ещё не проверены.
