# Аудит ответов звонящему — 0.6.5-test

## Исправленные дефекты по коду

| Дефект | Изменение |
|---|---|
| Возврат SmsManager считался отправкой | Для автоответа ожидаются SENT callbacks каждой части (до 45 с). SUBMITTED ≠ SENT ≠ доставка |
| Неизвестная SIM → SMS с карты по умолчанию | Отправка запрещена с явной ошибкой sms_sim_unknown, в том числе для быстрого SMS-ответа |
| Повторные параллельные события могли отправить две SMS | Сериализация по номеру/каналу; резервирование попытки до вызова Android |
| Частичная отправка могла выглядеть как полный успех | Сбор результатов всех частей; ошибка содержит число отправленных частей и коды Android |
| SIP/невалидный адрес с цифрами допускался как номер | Проверяется международный телефонный формат |
| Ошибки SMS выпадали из фильтра SMS | Фильтр использует тип события, не только успешный статус |
| Ручной быстрый ответ утверждал «отправлено» без проверки | Теперь «передана Android, отправка и доставка не подтверждены» |
| Редактор правил не запрашивал уведомления для мессенджера | Запрос POST_NOTIFICATIONS на Android 13+ |
| Ошибка безопасности при открытии мессенджера могла закрыть приложение | Обработка SecurityException, без ложного успеха |

При частичной отправке, неизвестном результате или исключении нет автоматической
повторной SMS и нет переключения на другую SIM. Резерв попытки действует 30 минут.
SENT означает подтверждение Android об отправке всех частей, НЕ получение
адресатом. Исторические события OK старых сборок теперь помечены как неизвестные.
Если процесс завершён до callbacks, останется SUBMITTED: это не успех.
Ожидание SMS не задерживает журнал перехвата и диспетчер переадресации.

## Мессенджеры: фактическое состояние

- WhatsApp: ссылка wa.me с номером и текстом, отправка ручная. Нет подтверждения
  существования аккаунта, отправки или доставки из внешнего приложения.
- Telegram/MAX/OTHER: системное меню отправки, приложение и чат выбираются вручную.
  Это НЕ автоматический ответ. Нет авторизованной интеграции с API этих сервисов.
- Никакой платной SMS вместо выбранного мессенджера не отправляется.
- Отказ уведомлений/блокировка канала фиксируется как ошибка. Закрытие меню не
  считается отправкой. Черновики не увеличивают счётчик отправленных SMS.

## MAX: что требуется для автоматической отправки

Проверена официальная документация POST /messages:
https://dev.max.ru/docs-api/methods/POST/messages
Отправка от бота использует access token и user_id либо chat_id, не номер телефона.
Нужна согласованная привязка номера звонящего к ID получателя и право бота писать
ему. Приложение не может угадывать адресата. Автоинтеграция MAX в этой сборке
НЕ реализована. Токены нельзя передавать в чат поддержки или хранить в Git.

## Автоматические проверки

Добавлены тесты: порядок/повтор callbacks, ошибки отдельных частей, неверные
индексы; проверка адресов; неизвестный статус не увеличивает счётчик SMS.
Существующие тесты: пропуск/PASS, скрытый номер, короткий номер, пустой текст,
лимит длины, cooldown, сохранение каналов, приоритет автоответчика, ограничения SIM.

## Что остаётся проверить физически (не заменяется unit-тестами)

1. На выбранную SIM сброс и одна SMS; другая SIM не затронута.
2. Нет SEND_SMS / нет READ_PHONE_STATE / SIM удалена: явная ошибка, без другой SIM.
3. Авиарежим, отсутствие сети, отказ оператора: ошибки SENT callbacks.
4. Длинная кириллица (multipart): результат каждой части; доставка на втором телефоне.
5. Быстрые повторные вызовы: отсутствие дублей SMS; исключение повторных звонков выключено.
6. Блокировка экрана, уничтожение сервиса, убийство процесса во время ожидания:
   не считать неподтверждённую отправку успехом.
7. WhatsApp отсутствует; Telegram/MAX без нужного чата; уведомления отключены;
   пользователь отменил ручную отправку: нигде не появляется «отправлено».
8. Проверка на двух SIM после перезагрузки/перестановки SIM.

«Все возможные отправления проверены» утверждать нельзя: реальных операторов,
аккаунтов MAX/Telegram/WhatsApp и подключённого телефона в CI нет.
