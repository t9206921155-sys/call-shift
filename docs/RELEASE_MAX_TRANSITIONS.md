## CallShift 0.8.16-max-transitions

Обновление поверх текущей версии, постоянная подпись, versionCode 48.
Продолжение 0.8.15 без перестройки основного экрана и повторной разработки поиска.

### Проверка переходов
- Найден пропуск в выходе из открытого чата к глобальному поиску: первый Android Back
  мог только скрыть клавиатуру. Раньше сценарий ждал список и останавливался через
  четыре секунды. Теперь допускается ровно один дополнительный Back, только если
  клавиатура была видна перед первым Back и исчезла, остались те же узлы заголовка/
  редактора, окно и подпись, единственное пустое поле, нет пароля и прошло не более
  четырёх секунд. Состояние погашается до действия. При уже открытом списке второго
  Back нет. Это не координатный клик и не цикл повторов.
- После ввода текста непосредственно перед нажатием отправки повторно читается
  актуальное дерево. Проверяются номер получателя, точный текст, окно MAX, SIM и
  маршрут, версия профиля, разрешения отправки, единственность заголовка/редактора/
  всех видимых полей и та же доступная кнопка. Если что-либо изменилось, нажатия нет,
  черновик сохраняется. Проверка поля после резервирования сама по себе не заменяет
  проверку после изменения интерфейса при вводе.
- Выбор кнопки отправки вынесен в единый метод: первичный поиск и окончательная
  проверка не расходятся по критериям. Сценарий по-прежнему снимается с выполнения
  ДО нажатия; нет автоматических повторов после неизвестного результата.

### Регрессии
Добавлены используемые самим сервисом политики переходов и unit-тесты:
- карточка с подписанным телефоном → +7/8 → пустая подсказка → точный текст → допуск
  нажатия; имя/чужой номер/отсутствие разрешения не проходят;
- отдельные отказы при изменении SIM/маршрута, окна, текста, версии, кнопки, количества
  редакторов, пароля или блокировки экрана;
- закрытие клавиатуры не считается выходом из чата; второй Back запрещён при любом
  несовпадении, отсутствии исходной клавиатуры или истечении срока.
Это unit-регрессии логики, не воспроизведение Accessibility MAX на реальном телефоне.
Выпускной workflow запускает весь прежний набор тестов, а не только новые файлы.

### Сценарий для телефона (тот же экран)
«Автоответ MAX» → SIM/копия и проверочный номер → проверка без отправки → отдельное
разрешение реальных ответов → одна тестовая отправка → получение у адресата.
Затем звонок на ту же SIM при действующем правиле «MAX — эксперимент UI».
Между тестами того же номера минимум 60 секунд; звонок подчиняется интервалу своего
правила. Ограничение MAX 5 реальных попыток за 24 часа не обходится. Таймер не отправляет.

Сохранены исправления 0.8.15: семантический ID профиля без зависимости от ручного
click source, ограниченное восстановление source при обучении, защищённый однократный
реальный тест, сохранение причины обучения, привязка проверки к конфигурации (не к
контакту), результат вместо повторной отправки.

SMS, правила и маршруты SIM не переписываются. Наличие исходного сбоя SOURCE_MISSING
не доказывает, что Android предоставит альтернативный ID. Если ни источник, ни
однозначная безопасная альтернатива недоступны, сохраняется честная остановка.
Полная отправка/доставка MAX на телефоне пользователя по-прежнему не подтверждена.
