## [0.2.5-m2] — 2026-09-25

### Исправлено
- «Только контакты» и «Только скрытые» стали взаимоисключающими (вместе правило не срабатывало никогда).
- SMS-автоответ нельзя сочетать с «Только скрытые» (некуда отправлять).
- «Протестировать номер» проверяет правило С ЭКРАНА (даже несохранённое), объясняет, почему условие не подошло,
  и перечисляет, что помешает при реальном звонке: нет роли, выключен переключатель, правило не сохранено,
  перебивает правило с меньшим приоритетом, скрытые номера не доходят до фильтра.
- «Журнал»: каждый перехваченный звонок записывается («Звонок перехвачен: звонок сброшен: правило «…»»),
  даже без переадресации — видно, доходят ли звонки до приложения.

### Изменено

- Русские названия в списке правил, журнале и окне «Протестировать номер».
- PAMYATKA.md: исправлены примеры (стратегии BLOCK нет), русские названия.

## [0.2.2-m2] — 2026-09-24

### Добавлено
- SMS-автоответ звонящему после отбоя (поле «SMS-автоответ» в правиле; вердикты `DISALLOW_REJECT` / `DISALLOW_AS_MISSED`).
- Анти-спам: не чаще 1 SMS на номер за 30 мин; скрытым и коротким (< 7 цифр) номерам не отправляется; длина ≤ 201 символа.
- SMS уходит с той же SIM, на которую поступил вызов (PhoneAccountHandle → subscriptionId); если SIM не определена — с SIM по умолчанию для SMS.
- Разрешение `SEND_SMS` (запрос из UI, `setup_device.sh`), события `SMS_REPLY` в журнале, тесты `SmsAutoReplyPolicyTest`.

## [0.2.0-m2] — 2026-09-24

Реализация milestone **M2: Профиль B (`ROLE_DIALER`) + системная выживаемость**.
Сборка: `standardDebug` (14 МБ) и `standardRelease` (2,9 МБ, R8 + shrinkResources, v3-подпись).
Unit-тесты домена — зелёные (0 failures).

### Добавлено в M2

**Профиль B (`ROLE_DIALER`) и экраны звонка (FR-P3, п. 3.5)**
- `DialerActivity`: экран набора номера (0–9, *, #, быстрый ввод '+' по долгому тапу '0',
  удаление/очистка, вызов через `telecom.dial`), обработка `ACTION_DIAL` и `ACTION_CALL`
  со схемами `tel:` и `voicemail:`.
- `CallShiftInCallService`: полноценный `InCallService`, зарегистрированный с
  `android.permission.BIND_INCALL_SERVICE` (не `exported="false"`), гарантирующий
  непустой binding во избежание отката Telecom на сторонний dialer.
- `InCallActivity`: полноэкранный интерфейс входящего и активного вызова поверх блокировки
  (`setShowWhenLocked`, `setTurnScreenOn`), кнопки ответа/отбоя, удержание (`hold`/`unhold`),
  маршрутизация аудио (громкая связь / наушник), отключение микрофона, DTMF-клавиатура,
  отображение вторичных вызовов и переключение между ними.

**DTMF-компенсация CLI (ТЗ п. 10.6, FR-4.6)**
- `DtmfTransmitter`: модуль формирования DTMF-последовательности тонов для передачи
  исходного номера звонящего цели (АТС/IVR) при переходе вызова в статус `STATE_ACTIVE`.
- Поддержка настраиваемых префиксов (например, `*9`) и завершающих символов (`#`).

**Шторка быстрых настроек и системная интеграция**
- `CallShiftTileService`: Quick Settings Tile для переключения переадресации в 1 тап (FR-8.3).
- `ExternalRetryQueueImpl`: очередь повторной доставки внешних событий на базе `WorkManager`
  (FR-6.3, ограничение 100 записей, экспоненциальный backoff).

## [0.1.0-m1] — 2026-09-24

Референс-реализация milestones **M0 + M1** по ТЗ п. 17. Сборка: `standardDebug` и
`standardRelease` (R8 + shrinkResources), 38 unit-тестов домена — зелёные.

### Добавлено

**Перехват вызовов**
- `CallScreeningService` с бюджетом 2800 мс и fail-open-поведением (FR-2.1, FR-2.8, NFR-2).
- Ответ системе методом `respondToCall(Call.Details, CallResponse)` — с учётом реальной
  сигнатуры платформы (Приложение E, P-1).
- Абсолютный пропуск экстренных номеров: нормализатор + локальный список коротких кодов
  (FR-2.6, E-04, Приложение E P-9).
- Обработка анонимных вызовов (`handle == null`) отдельной веткой условий (FR-2.4).
- Пропуск self-managed вызовов (VoIP других приложений) по умолчанию (FR-2.7, E-12).
- Best-effort определение SIM: reflection → `extras` → «не определена» (FR-2.5, Приложение E P-2/P-3).

**Движок правил**
- `RuleEngine` с приоритетами, расписанием (включая окно через полночь), условиями
  `number_match` / `number_in_list` / `in_contacts` / `anonymous` / `sim` / `network` /
  `battery_below` / `line_state` (FR-1.2…FR-1.5, п. 9.4, 10.2).
- Маски номеров `+35840*`, `*4567`, `+35840???????` с валидацией при сохранении (п. 10.1, UI-4).
- Нормализация E.164 через libphonenumber, регион по умолчанию FI (FR-3.3, п. 10.1).
- Политика по умолчанию при отсутствии совпадений (FR-9.2).
- Таймаут движка и любая ошибка → `PASS` с фиксацией причины в журнале (NFR-2).

**Стратегии перенаправления**
- **S1 (MMI)**: `*21*`, `*61*<номер>**<сек>#`, `*62*`, `*67*`, `##002#`, `##004#`,
  `*#21#`… с выбором SIM через `EXTRA_PHONE_ACCOUNT_HANDLE` и приёмом ответа USSD через
  `ResultReceiver` + `EXTRA_USSD_RESPONSE` (FR-3.1…FR-3.8, Приложение A, Приложение E P-6/P-7).
- **S2 (callback-дозвон)**: отбой → задержка 800 мс → `placeCall` на цель, 1 ретрай,
  фиксация результата (FR-4.1…FR-4.7, п. 10.5).
- **S4 (уведомление/эскалация)**: локальное уведомление high-priority с кнопкой
  «Перезвонить», Telegram Bot API, произвольный HTTP-webhook (FR-6.1…FR-6.4).
- **S3 (SIP)**: зарегистрирована заглушка, честно возвращает `NotAvailable` с указанием
  текущего уровня аудио-моста L0–L3 (п. 4.5, FR-A1, R-5) — реализация в M3.

**Защитные механизмы (п. 10.3)**

- Антишторм: лимит дозвонов за период (по умолчанию 3 за 10 мин) — `guard_storm`.
- Cooldown 30 с на повторный дозвон тому же звонящему — `guard_cooldown`.
- Проверка премиум-диапазонов цели (FR-4.3, E-10).
- Валидация правила в UI: цель не должна совпадать с собственным номером (FR-4.3).

### Известные ограничения этой сборки

| Ограничение | Причина | Где описано |
|---|---|---|
| Профиль B (`ROLE_DIALER`) не реализован: нет собственного dialer-UI | Требует полноценного dialer (FR-P3); milestone M2 | README §5, ТЗ п. 17 |
| SIP-мост (S3) — заглушка | Нужен SIP-стек + self-managed `ConnectionService`, согласование лицензии GPL/LGPL | ТЗ п. 4.5, п. 21 (источник 8) |
| Хранилище — JSON-файлы и SharedPreferences вместо Room/DataStore/WorkManager | Осознанное упрощение M1; порты `RuleStore`/`SettingsPort`/`EventRecorder` изолируют замену | ТЗ п. 6.5 |
| SIM входящего вызова определяется best-effort | `Call.Details.getPhoneAccountHandle()` — `@hide` для сторонних приложений | Приложение E, P-2 |
| `setSkipCallLog` не используется | Игнорируется системой для сторонних приложений; вызов остаётся в системном журнале с типом `BLOCKED_TYPE` | Приложение E, P-11 |
| Foreground service `phoneCall` не запускается | Android 14+ требует активный вызов для этого типа FGS; дозвон выполняется в application scope сразу после `respondToCall` — при агрессии OEM нужен переход на `InCallService` (M2) | ТЗ п. 11.1 |
| Tile/виджет, пресеты, гео-условия, SMS-эскалация | FR-8.3/8.4, FR-6.2 (SMS), M2 | README §5 |

### Инженерные заметки (важно для следующей итерации)

1. **Таймаут движка:** `withTimeoutOrNull` и `withContext(dispatcher)` должны находиться в
   одном контексте корутины. Вложенный вариант на тестовом диспетчере (виртуальное время)
   давал ложный `engine_timeout_budget_3000ms`. Исправлено в `RuleEngine.evaluate`.
2. **Имена unit-тестов:** не-ASCII и символы `. ; [ / < > :` в backtick-именах ломают
   сборку (`InvalidPathException` / «Name contains illegal characters») на JVM с
   не-UTF-8 `sun.jnu.encoding`. В `gradle.properties` заданы `sun.jnu.encoding=UTF-8`
   и `file.encoding=UTF-8`, имена тестов — ASCII (Приложение E, P-10).
3. **Память сборки:** на машине с 2 ГБ ОЗУ релизная сборка с R8 умирала по OOM-killer.
   Решение: `org.gradle.jvmargs=-Xmx1024m … -XX:+UseSerialGC`, `kotlin.daemon.jvmargs=-Xmx640m`,
   `org.gradle.parallel=false`, `--max-workers=1`, плюс swap ≥ 4 ГБ. В CI (GitHub Actions
   `ubuntu-latest`, 7 ГБ) ограничения можно ослабить.
4. **Схема подписи APK:** при `enableV3Signing = true` apksigner поглощает блок v2,
   поэтому `apksigner verify` сообщает `v2: false, v3: true`. Это штатное поведение,
   а не дефект сборки: v3 действует на всех API ≥ 28 (наш `minSdk`) и добавляет ротацию
   ключей. ТЗ п. 15.1 уточнён в редакции 1.1 («v2 или v3»), поставочная сборка — v3.
5. **Правила резервного копирования:** в `backup_rules.xml` / `data_extraction_rules.xml`
   `exclude` должен идти до `include`, иначе lint-проверка `FullBackupContent` падает.
